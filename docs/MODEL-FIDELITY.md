# Models and limits

The Observatory is a set of interactive physics models with idealized geometry and illustrative parameters. Each scene states its model; none is an exact reconstruction of a real object.

The equations can be exact within a chosen model while that model omits real effects. Numerical error, model error and an unmeasured result are different things. The checks below are implementation checks, not scientific certification. See the [developer guide](DEVELOPING.md#unattended-test-runs) for commands; an unavailable or unrun check supplies no accuracy evidence.

## Chaos labs

Three-body forces and the displayed energy use the same softened potential, `U = -sum(i<j) mi*mj/sqrt(rij² + epsilon²)`. The launch nudge changes the cyan body's velocity before subtracting the system's centre-of-mass velocity. It therefore changes relative motion without giving the entire lab a net drift. The figure-eight starts from [Chenciner and Montgomery's equal-mass orbit](https://arxiv.org/abs/math/0011268); softening is an explicit modification. The equal-mass rotating triangle uses the circular angular speed for the softened force, and is unstable to perturbations.

The pendulum equations follow the point-mass, massless-rod model [derived by Erik Neumann](https://www.myphysicslab.com/pendulum/double-pendulum-en.html). Its error readout divides energy change by `3mgL`, rather than by initial energy, which can be near zero. The amber and cyan drawings have a tiny depth offset for visibility; physical separation is measured in their common plane.

Both labs retain elapsed-time remainders and advance in fixed steps as frames arrive. Speed changes the number of steps, not their size. Trails sample at 60 points per simulation-time unit with a bounded 16-unit history and survive pausing. The app caps wall-frame time at 0.05 s, so overloaded rendering slows the experience rather than catching up without a work limit. Replay uses the same initial data and no randomness.

Run [the production-model checks](../Tools/check-chaos.ps1) for the fixtures and tolerances in [PhysicsChecks.cs](../Tools/chaos/PhysicsChecks.cs). Passing those checks verifies the stated numerical cases, not every slider value or arbitrarily long trajectories. The Unity editor was unavailable on the implementation machine; rendering, scene input and performance remain unobserved.

## Reading results

Use a result only for the tested fixture, settings and revision. Record units, reference, tolerance and elapsed simulation time. Separate functional failures from slow performance samples and hang-guard timeouts. A native Unity/GPU run is needed for shader output claims; CPU calculations alone do not verify the GPU. Improving a label does not resolve a separate numerical or mechanics issue.
